# 传统工艺来源授权账 · 生态采材与工坊用料服务

面向桦树皮工艺合作社：林地管理者发布**可采区域、树龄条件、季节窗口、单株上限、恢复观察要求**；
采集队申请额度、弱网记录采材与交接；工坊把合规材料分配到作品，并支持边角料回收、多人合制、退料的**物料守恒**；
公开验真只给来源结论，不泄露敏感林点。

## 领域规则

- **规则版本化**：林地规则按版本发布，许可发放时锁定当时版本；之后的规则修订只约束后续新采集，已采材料仍按当时规则接受审计。
- **并发额度不超总量**：同一许可的额度申领串行判定并扣减（`request_id` 幂等），并发请求不会在判定间隙同时通过。
- **隔离制度**：新采材一律先进隔离；存在越界、证照缺失/过期、季节窗口外、树龄不足、单株超限、树体重占、恢复观察未完成任一情形，不得进入交接与工坊。
- **恢复观察**：按规则生成观察任务（观察期 + 必检项）；观察期届满且全部检查完成才放行，其余违规在此时转为拒收。
- **弱网友好**：`record_id` / `request_id` 由现场端预生成，重传幂等；也可只传已模糊的格网定位，不上传原始坐标。
- **定位模糊化**：坐标只以约 2 km 格网单元在管理端留存（`blurLocation`），公开渠道不出现坐标、格网、树号、许可号、采集队。
- **物料守恒**：每批次 `Σ 领料 = 成品占用 + 边角料`；退料恢复凭证可用量并更新作品净用量；边角料回收不超产；同一凭证被多个批次/合制引用时**只按净用量计一次**。
- **双向追溯**：作品 → 去重后的采材凭证；凭证 → 引用它的作品。对账按林地 × 月份核对实际消耗、退料、隔离重量、恢复任务与剩余额度。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 项目标识 |
| POST | `/admin/forestlands` | 发布林地与首版规则（含边界、季节、树龄、单株上限、恢复要求） |
| POST | `/admin/forestlands/:id/revisions` | 修订规则（新版本，只约束后续采集） |
| GET | `/admin/forestlands/:id` | 查看当前规则（不返回精确边界） |
| POST | `/admin/permits` | 发放许可（总量、有效期、必备证照，锁定规则版本） |
| GET | `/admin/permits/:id` | 许可与剩余额度 |
| POST | `/admin/permits/:id/close` | 关闭许可 |
| **POST** | `/api/permits/:id/quota-requests` | 采集队申领额度（`request_id` 幂等；不足返回 409） |
| POST | `/api/harvest-records` | 弱网上报采材（坐标自动模糊化，先进隔离） |
| POST | `/api/recovery-checks` | 回填恢复检查，观察期届满自动放行 |
| POST | `/api/handoffs` | 采集队→工坊交接（仅放行凭证可交接） |
| POST | `/workshop/crafts` | 登记作品与制作者份额（来自 `craft_record.json`，份额和为 1） |
| POST | `/workshop/batches` | 工坊用料批次（强制守恒，逐笔校验凭证余量） |
| POST | `/workshop/batches/:id/recycle` | 边角料回收（不超边角料总量） |
| POST | `/workshop/returns` | 退料（不超本批领用量，恢复凭证可用量） |
| GET | `/verify/:craftId` | **公开验真**：只返回合规结论与汇总来源结论 |
| GET | `/admin/crafts/:id/trace` | 作品 → 凭证（去重，标净用量） |
| GET | `/admin/records/:id/trace` | 凭证 → 作品 |
| GET | `/admin/reconciliation?forestland_id&month` | 林地×月份对账：消耗/退料/隔离/恢复任务/剩余额度 |
| GET | `/admin/audit-fingerprint` | 审计日志条数与 SHA-256 指纹 |

> 写接口经单进程互斥锁串行化，每次写完自动运行 `assertConservation` 守恒自检；失败返回 500 且不外发结果。

`contracts/craft_record.json` 保存公开的领域样例，用来约定外部数据的名称与层级；样例不含真实个人资料、业务凭据或生产连接信息。

执行 `npm run check` 可检查服务身份，运行 `npm test` 可核对基础契约、领域规则与 HTTP 竞态/隐私。服务启动后，`/health` 返回项目标识。
